# 任务进度表与主动提交

2026-11-04更新：后端已部署，公网确认questSubmissionVersion=1；实际领取与Godot仍待联调。本文件只交付接口与页面契约，不修改Godot源码。目录入口见[索引](README.md)，本次任务见[道具与任务详情](道具系统与任务详情接入交接.md)。
完整字段以[普通任务主动提交与结算页面交接](普通任务主动提交与结算页面交接.md)为准。

|服务端状态|进度表|可显示按钮|奖励显示|
|---|---|---|---|
|IN_PROGRESS|按objectives逐项勾选，conditions显示当前条件|原目标行动、符合条件时放弃|原配置说明，不表示已入账|
|READY_TO_SUBMIT|全部目标锁定，仍占任务栏|canSubmit=true才可提交；放弃仍需1声望|submission.rewardPreview冻结预览，明确“尚未领取”|
|COMPLETED|completedQuests按playerQuestId显示每次实例|不能再次提交|submission.rewardPaid或历史reward字段|

以playerQuestId作列表和按钮主键，不用questId合并同名任务。
所有更新来源（actions、roll、quests重新查询）均使用相同objectives/submission结构。
questUpdates延续增量语义，不保证每次行动列出全部任务；没有条目不代表任务被移除。
回合切换、当前位置变化及重连后，使用既有quests查询刷新当前条件和提交资格，不能沿用旧回执的canSubmit。
014的stayState只表示是否继续参加停留计数，不是提交资格；达标后的旧计数原因QUEST_FINALIZED也不能替代任务status。
当前位置conditions变为false，不取消已锁定目标；不要据此置灰已经允许的提交按钮。
014进度未满时离开仍清零；2/2后显示待提交，不因离开清零。
END达标最早下一个个人回合提交，不要把全局轮数当作个人回合。

## 结算页面

一次SUBMIT_QUEST成功后，以questSettlement展示“本次实际金币/声望/伙伴加成”和“结算后余额”。
coinsGranted已包含partnerBonusCoins，伙伴加成只作明细，不能加第二遍。
随后页面确认仅打开playerViewState.engineState.pendingReward，不发送第二次SUBMIT_QUEST。
没有队首或实际抽到0张，不生成空选择弹窗；有deckDraws不足提示则正常展示。
队首属于别人时等待轮询，不显示其私有候选。背包满时仍使用现有FIFO合法整理能力。

## 网络与恢复

重复点击禁用；超时不能认为失败。重试使用原requestId和完整原body，或刷新状态确认结果。
旧回执允许不含新字段；新鲜player-view的questSubmissionVersion=1才代表服务已支持。
重启后先恢复active-session/player-view与quests，再按服务器阶段和队首恢复页面。
已正式完成不会再次领固定奖励；已有pendingReward继续处理，不重建候选。
