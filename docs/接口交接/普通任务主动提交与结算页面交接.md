真实隔离HTTP字段节选见[014、038、042、052响应样例](普通任务主动提交_隔离HTTP样例.md)。样例ID只属于隔离库，不能用于公网请求。

## 能力与兼容

读取新鲜的 `GET /api/v1/games/{gameId}/player-view`，以
`data.engineState.questSubmissionVersion=1` 判断能力，不能使用 `movementRulesVersion`。
现有EVENT_V2已开放的普通任务统一生效，包括旧CORE_1～CORE_9对局；不补卡、不重建副本或manifest。
074、失败补偿、特殊直接胜利和未准入卡牌不在本批范围。
旧requestId原响应原样重放，不补新字段；已有COMPLETED不追回或重发奖励。

## 状态与锁定

`IN_PROGRESS → READY_TO_SUBMIT → COMPLETED`。

目标全部达成只冻结奖励、判定边际、大麦加成、证据事件和最早提交个人回合；
目标状态停止变化，计时器不再终止任务，014实际离开不再清零。
此时不发奖、不抽选择奖励、不发布QUEST_COMPLETED、不弃牌，仍占任务栏。
未达标任务继续原目标算法，014仍会在实际离开时清零。
START/回合中达成可在该个人回合MIDDLE提交；END达成最早为下一个人回合，额外回合正常计入。
待提交任务本身不阻止END，不新增自动提交或离线代领奖规则。

旧READY_TO_SETTLE查询映射为待提交，保留原冻结金额；达成时间从该实例的历史事件消费证据恢复。
旧QUEST_FIXED_REWARD自动效果不再兑现，只允许把尚未领奖实例转换为新状态。
旧副本的settlement_phase字段不重写；在questSubmissionVersion=1下它不再决定普通任务自动发奖，唯一兑现入口为SUBMIT_QUEST。
历史证据或快照缺失返回GAME_SNAPSHOT_MISSING，不能按照现有配置猜测奖励。

## 提交请求

继续 `POST /api/v1/games/{gameId}/actions`，Bearer认证。

```json
{
  "requestId": "submit-quest-click-unique-id",
  "playerId": 11,
  "stateVersion": 30,
  "actionType": "SUBMIT_QUEST",
  "payload": {"playerQuestId": 101}
}
```

payload只允许正整数playerQuestId，不接受questId替代、金额、完成标志或奖励选择。
执行时核验真实实例归属、RUNNING、本人回合、MIDDLE、最早个人回合、无暂停/待骰/奖励队首。
不重新核验已经达成时使用过的地点、道具、伙伴或属性，不额外收费。

成功响应仍为Result包装，新增可空 `data.questSettlement`：

```json
{
  "playerQuestId": 101,
  "questId": 142,
  "coinsGranted": 5,
  "prestigeGranted": 2,
  "partnerBonusCoins": 2,
  "coinsAfter": 8,
  "prestigeAfter": 4,
  "pendingItemRewardCount": 0
}
```

这是字段说明示例，实际HTTP样例以验收目录原始回执为准。
coinsGranted是本次金币入账总额，已包含partnerBonusCoins，不能再次相加。
余额独立返回，不以余额差计算收益。pendingItemRewardCount是实际产生的待选道具奖励数量，不是已获得物品数。
只有现有领取动作实际成功后才有ITEM_ACQUIRED；抽取不足信息使用deckDraws。
本次questUpdates含最终COMPLETED和全部目标，playerViewState含最新余额和全局FIFO队首。
无本次任务提交时questSettlement为null或省略；旧历史回执允许缺少该字段。

## 查询与进度表

继续 `GET /api/v1/games/{gameId}/quests?playerId=...`。
进行中和待提交都在quests，完成实例在completedQuests；每次接取以playerQuestId独立显示。
保留objectives、conditions、progress、checkAttributes和stayState，不解析中文描述。
PlayerQuestVO及QuestUpdateVO均增加可空submission：

```json
{
  "protocolVersion": 1,
  "targetsLocked": true,
  "achievedPersonalTurn": 5,
  "earliestSubmitPersonalTurn": 6,
  "canSubmit": false,
  "unavailableReason": "NOT_OWN_TURN",
  "rewardPreview": {"coins": 3,"prestige": 2,"partnerCoins": 2,"itemCount": 0},
  "rewardPaid": null
}
```

rewardPreview.coins是冻结基础/边际金币，不含单列partnerCoins；总预览金币为二者之和。
rewardPaid只在COMPLETED展示实际入账快照，其coins包含伙伴加成。
原quests列表的rewardCoins/rewardPrestige/rewardItemCount仍是牌面配置字段，不代表已经入账；
questUpdates中的同名字段在待提交时为0，完成后为既有结算快照。
结算页只用本次questSettlement；进度页冻结预览用submission.rewardPreview，历史已付用submission.rewardPaid。
未达标时targetsLocked=false，回合字段及rewardPreview为null，reason=TARGETS_NOT_ACHIEVED。
旧完成实例不补造达成证据，targetsLocked=false且回合字段为null；保留其已保存的奖励事实。
当前位置conditions可为false，但已锁定目标仍completed=true且不影响提交资格。

稳定不可提交原因：TARGETS_NOT_ACHIEVED、QUEST_FINALIZED、GAME_NOT_RUNNING、NOT_OWN_TURN、
GAME_PAUSED、NOT_MIDDLE_PHASE、PERSONAL_TURN_NOT_REACHED、CHECK_ROLL_PENDING、PENDING_REWARD_BLOCKED。
canSubmit与服务端权威入口采用同一资格检查；客户端仍须处理并发状态变化后的拒绝。

## 客户端结算页

ITEM奖励队首及候选字段以[ITEM奖励候选准确契约](ITEM奖励候选准确契约.md)为准，含完整隔离JSON。候选的cardId用于领取，itemId用于卡图，名称取configuration.item_name；后端没有候选顶层itemName。领取同时校验队首与候选canExecute，不把canResolve当领取资格。

1. 新鲜player-view确认协议能力，任务进度页显示“待提交”和服务端canSubmit/原因。
2. 点击提交生成一个新requestId，禁用重复点击，等待同一次请求结果。
3. 展示questSettlement实际入账、单列伙伴加成与余额；不要把奖励预览当作已入账。
4. 点击结算页“确认”仅打开已存在的engineState.pendingReward界面，不再次提交或生成奖励。
5. FIFO可能先属于其他玩家，必须依服务端队首身份展示；容量不足时使用既有合法整理/放弃。
6. 没有实际候选时不打开空选择窗口；展示deckDraws应抽、实抽及不足说明。

原网络重试必须保留requestId、完整请求体和stateVersion；首次响应丢失也重放首次结果。
同ID改字段返回REQUEST_ID_CONFLICT。刷新后要发起新操作使用新ID及最新版本。
新ID提交已完成实例被拒，不会再次领奖。普通声望胜利仍在END及相关待办完成后检查。

## 放弃与错误

ABANDON_QUEST沿用既有payload及playerQuestId校验，支持READY_TO_SUBMIT；需1声望。
放弃不领奖，释放栏位、进入弃牌，继续CORE_8耗尽回收，不立即洗回。
SUBMIT_QUEST不是奖励期间整理白名单，已有队首会阻止提交；放弃仍按既有整理规则执行。

保留错误码：PARAM_INVALID、AUTH_PERMISSION_DENIED、ACTION_NOT_AVAILABLE、GAME_PHASE_BLOCKED、
CHECK_ROLL_PENDING、GAME_STATE_VERSION_EXPIRED、REQUEST_ID_CONFLICT、GAME_SNAPSHOT_MISSING。
非法/回滚操作不留成功事件或成功幂等记录。

## 事件边界

目标达成唯一发布QUEST_TARGETS_ACHIEVED，保存来源证据和资格，不作为正式完成。
SUBMIT_QUEST唯一兑现，依实际变化发布COINS_GAINED/PRESTIGE_GAINED、待选奖励/抽牌事实、弃牌和QUEST_COMPLETED。
已用事实与新事件均沿用操作scope、FIFO缓冲和原事务；生命周期审计不恢复旧任务触发链。
放弃沿用PRESTIGE_SPENT、QUEST_ABANDONED及实卡弃牌事实。查询不写事件或状态。
