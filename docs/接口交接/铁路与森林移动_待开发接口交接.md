# 铁路与森林移动：接口定稿（已部署）

更新时间：2026-11-04。统一交接入口见[索引](README.md)。

**状态：已于2026-11-03部署，并保留在11月4日主动提交版本中。** 文件名为兼容已有链接保留；最终契约以[第8节](#8-最终接口契约)为准，第1～7节保留开发前背景和草案，不是现网承诺。实际接入须识别新鲜movementRulesVersion=2，不凭CORE_9名称判断。本轮只整理文档，不修改Godot或声称实际玩法验收完成。

## 1. 已核对的现状

- 当前已交付版本为EVENT_V2 / CORE_9_PUBLIC_SHOP，公共地图直接读map_cell/map_edge，不恢复地图副本。
- 2026-11-03只读GET /api/v1/maps/main：code=1、138格、385条边、12个STATION车站、13条STATION_ROUTE连接；车站全部连通，未发现铁路悬空引用、自连接、重复连接或无线路车站。此结果是结构/连通性检查，不是逐线对照纸图的完整性认证。
- 铁路站点在map_cell，连接在map_edge；当前票价由代码计算，不是每条线路单独配置价格。
- 当前MOVE_ONE_STEP仍可免费利用铁路边；USE_RAILWAY只支持直接相连车站，通常1金币+1速度且保留免票分支。
- 当前movable-cells仅为普通一步目标；没有已实现的铁路目标查询模式。movement没有costCoins或coinsAfter。
- 当前森林只有通行能力门槛，没有完整方向骰移动流程。不能把解开EVERFREE门槛说成完成特殊移动。

## 2. 已确认的玩法规则

### 2.1 普通移动与铁路

1. 普通移动一次请求只走一步，提交targetCellId，不提交整条路线。
2. 铁路是独立USE_RAILWAY行动，玩家必须在STATION格；目标必须是有STATION_ROUTE直接连接的STATION格，不是QR坐标相邻。
3. 每次成功乘一站固定消耗1金币和1行动值。行动值当前对应currentSpeedPoints，不新增另一套行动资源。
4. 所有免票暂不开放；MOVE_ONE_STEP不能再借铁路连接免票。
5. 多站由玩家一次次提交；不做跨站直达、最短路线报价、自动连续乘车或中间站虚拟经过。每次到站是真实到达，可触发对应任务。
6. 没有足够资源、地点不符、目标非直接相连车站等非法请求，拒绝执行，不扣费、不改位置。正常请求仍受当前回合、MIDDLE阶段、待办、待骰、暂停、在线、版本和归属检查。

### 2.2 森林普通移动

1. 是否掷骰只看出发格是否属于森林区域。森林外进入不掷骰；森林内移动、从森林离开都掷骰。
2. 包含旧城堡、泽可拉小屋、韵律之树。正式图这些格子有MAZE标签；不能只检测EVERFREE或中文名称，也不能把地图视觉颜色当服务端规则。
3. 先选相邻合法目标，再由前端投物理骰，按需要申请重投，最后提交整数1～6。前端不提交真实落点、属性加成、难度、成功与否或费用。
4. 以出发格面向目标为方向：2～5到目标，1左偏一个六边形方向，6右偏一个方向；左右不随摄像机旋转。
5. 偏移仍以原出发格为中心，计算旋转60度后的邻格，不是到目标格后再多走一步。无边界合并，不重掷到合法为止。
6. 偏移落点不存在、无连接道路、道路关闭、不可通行裂缝或动态封锁：留在出发格，仍消耗本次1行动值。其他既有持牌通行条件继续由服务端校验，不顺带开放跨缝。
7. 正常森林移动不再要求持有森林免疫才能执行；泽可拉和森林免疫伙伴本批仍关闭。
8. 固定骰点适用，固定6就是右偏。允许既有甜贝儿重投链：每个个人回合一条链、同一check，先免费一次再可花1社交一次，机会不跨check转移；只确认最新结果。
9. 方向骰不加属性、不比较难度。发生偏移不等于属性判定失败；原地停留不等于HTTP/事务异常。
10. 只在真实改变位置时发布ARRIVE_CELL；留在原格不伪造到达/离开，不重置014完整停留任务。

### 2.3 应用范围

新规则需作用于当前已有测试局，不要求清局重建。保留账号、公共配置、卡牌副本、任务进度、历史事件、已完成判定及原requestId回执；不把历史免费铁路补扣费用。本轮文档更新不会使现网立即采用新规则。

## 3. 复用哪些接口

共同前缀/api/v1，除maps/main外需Bearer；局内playerId取player-view中当前账号对应玩家。

| 路径 | 当前情况 | 本批目标 |
|---|---|---|
| GET /games/{gameId}/map | 已有完整公共图 | 保持静态地图结构，不让客户端用图推断最终资格 |
| GET /games/{gameId}/player-view | 已有位置/阶段/资源/待办/待骰 | 增补移动能力版本标识，支持识别新实现及恢复森林准备 |
| GET /games/{gameId}/available-actions?playerId=... | 已有MOVE_ONE_STEP及USE_RAILWAY资格 | 与目标查询及实际执行共用规则 |
| GET /games/{gameId}/players/{playerId}/movable-cells | 当前仅普通一步目标 | 可选actionType区分普通目标与相邻铁路目标，保留数组包装 |
| POST /games/{gameId}/actions | 已有两种移动action | 普通直接移动/森林准备/铁路逐站执行 |
| GET /games/{gameId}/checks/pending | 当前查询待骰 | 支持森林出发格及所选目标恢复 |
| POST /games/{gameId}/checks/{checkId}/reroll | 已有重投授权，无中间点数 | 支持森林业务，沿用链及费用 |
| POST /games/{gameId}/checks/{checkId}/roll | 已有最终点数确认 | 森林最终返回实际位移及耗费 |

不增加重复地图、专用第二套掷骰、跨站寻路或已完成WORK查询接口。下面的参数/字段为建议实现草案，不是现网已有能力。

## 4. 历史技术草案：目标、能力和请求（由第8节替代）

建议扩展现有目标查询，省略actionType仍表示MOVE_ONE_STEP；显式值仅允许MOVE_ONE_STEP或USE_RAILWAY，未知值返回参数错误，不静默退成普通移动。

~~~http
GET /api/v1/games/{gameId}/players/{playerId}/movable-cells?actionType=USE_RAILWAY
Authorization: Bearer <accessToken>
~~~

data继续为MapCellVO数组，在本次目标查询中增加costSpeed、costCoins、requiresRoll。字段名待实现验收；普通地图对象不必增加无意义的费用字段。能力标识建议用player-view.engineState.movementRulesVersion整数，值2才表明本批目标模式与方向骰协议已支持；缺失时不能假设新协议可用。旧服务器可能忽略未知query，所以不能靠HTTP200探测铁路模式。

下面是待实现的铁路候选data数组结构示例，ID/费用仅作结构说明，不是一次真实请求结果：

~~~json
[
  {
    "cellId": 100086,
    "cellCode": "F4",
    "cellName": "中心城火车站",
    "cellNameText": "中心城火车站",
    "q": 5,
    "r": 5,
    "interactionTags": ["STATION", "CANTERLOT_TRAIN_STATION", "QUEST_POINT", "NORMAL"],
    "costSpeed": 1,
    "costCoins": 1,
    "requiresRoll": false
  }
]
~~~

示例格子及QR取自正式种子，仅作字段说明，不代表当前调用结果或实时行动资格，不得写成客户端固定候选。正式格子坐标和其他原字段应完整保留。铁路目标只返回直接邻站，不返回全铁路网中所有可达车站。

铁路请求沿用现有结构；下面仅为结构示例，需实际目标、playerId和stateVersion：

~~~json
{
  "requestId": "d154dced-7b46-4e58-8f21-950803ebd45a",
  "playerId": 1001,
  "stateVersion": 8,
  "actionType": "USE_RAILWAY",
  "payload": {"targetCellId": 100086}
}
~~~

普通移动/森林准备使用同一请求结构，actionType为MOVE_ONE_STEP。是否进入森林待骰以服务端响应为准；客户端可根据requiresRoll提示，但不能自己执行实际位移。

## 5. 历史技术草案：森林准备与最终回执（由第8节替代）

建议复用PendingCheckVO并增加可空movementContext；businessType使用FOREST_MOVE。准备成功返回GameActionResponse.resultType=CHECK_ROLL_PENDING，movement为空，pendingCheck提供以下出发/目标信息和现有checkId、授权、版本、固定点数、期限及资格。

~~~json
{
  "businessType": "FOREST_MOVE",
  "movementContext": {
    "fromCellId": 100020,
    "requestedTargetCellId": 100022,
    "costSpeed": 1,
    "costCoins": 0
  }
}
~~~

上例仅是pendingCheck的新增部分草案，不是完整响应。建议与现有判定费用一致，在准备事务扣一次行动值并持久化；确认/重投不再次扣移动费用。等待期间位置不变；即使准备后速度为0，也允许正常确认。

重投与最终/roll请求体不变，前端不上传中间骰点，不得用旧check的授权/目标；最终确认示例：

~~~json
{
  "requestId": "234c0568-b783-45d7-bdc5-dccfaed7ca37",
  "stateVersion": 10,
  "authorizationRound": 1,
  "dice": 6
}
~~~

建议CheckRollResponse增加可空movement复用MovementResultVO；保留submittedDice/effectiveDice及最终playerViewState、questUpdates等。方向骰checkResult可为空，不伪造六维属性、难度或success。旧QUEST/WORK/PARTNER_RECRUIT响应不改变含义。

建议movement保留全部原字段，并追加costCoins、coinsAfter、movementOutcome、stayReason：

| 字段 | JSON类型 | 草案含义 |
|---|---|---|
| costSpeed | integer | 本次移动费用，森林指准备时已扣的1，不是最终再扣1 |
| remainingSpeed | integer | 完整结算链后的行动值余额 |
| costCoins | integer | 本次行为实际支付金币；普通/森林0、铁路1，不是余额差 |
| coinsAfter | integer | 完整结算链后的金币余额，可能包含独立任务奖励 |
| movementOutcome | string | MOVED或STAYED；只说明是否真实位移 |
| stayReason | string/null | STAYED时稳定原因码，具体枚举在实现后列全；MOVED为null |

铁路直接在actions的movement返回结果；森林在最终/roll返回。requestedTarget是玩家所选，actualTarget是服务端最后位置，原地时actualTarget等于from。方向骰合法结算但原地停留返回code=1和STAYED；非法请求/技术异常继续用原统一错误包装，不伪造付费成功。

## 6. 客户端接入顺序与等待门槛

1. 后端验收并部署、正式更新DTO/样例后，再开启新流程；本轮不因为文件存在而直接使用草案参数。
2. 登录、恢复本局身份、建立心跳；读取player-view及移动能力版本。客户端不能用CORE_9批次名推断新功能已经部署。
3. 普通目标和铁路目标分别查询，按钮受available-actions/待办/资源约束。铁路选择后每次仅提交一站；普通移动可能直接完成，也可能进入森林待骰。
4. 森林等待时不移动棋子、持续心跳；支持重投授权及最终确认，按effectiveDice和movement展示。
5. 按actualTarget落位，更新playerViewState/questUpdates/nextAvailableActions；原地停留也更新剩余资源，不自动再提交同一移动。
6. 新操作新requestId；未知网络结果原requestId、原路径、原stateVersion和完整原body重试。不得因准备后位置未变就另发请求重复扣费。
7. 不清理对局、不调整相机/模型映射来改变左右、不自行计算真正扣费或发奖。已有WORK异常恢复/完成结果查询继续暂缓。

## 8. 最终接口契约

2026-11-03本地定稿并完成部署，11月4日版本继续保留。本节覆盖上文技术草案，文件名仅避免已有链接失效。后台实现与隔离证据见后端`docs/EVENT_V2铁路与森林移动交付说明.md`、`target/verification-railway-forest/验收结果.md`；部署依据见`target/ops-quest-submit-20261104/普通任务主动提交结算_部署完成报告_20261104.md`。隔离回执不等于公网玩法或Godot验收。

### 8.1 能力与目标

新鲜GET player-view的 `data.engineState.movementRulesVersion` 为integer 2。没有该字段就不要启用新流程；历史重放中的旧视图不能用于能力探测。已有CORE_9无需重新建局，manifest/卡池/历史响应不改；其他支持旧批次也采用新移动，不额外开放其关闭伙伴或旧属性主动骰能力。

`GET /api/v1/games/{gameId}/players/{playerId}/movable-cells?actionType=USE_RAILWAY` 查询直接邻站；省略或MOVE_ONE_STEP查非铁路的一步目标。未知值PARAM_INVALID。Bearer及本人权限不变，data数组不为null；非回合、阶段不合法、离线、暂停、奖励/待骰阻塞或资源不足时没有可行动目标。查询不扣费、不补点。

数组沿用原MapCell字段；仅目标查询额外返回 `costSpeed:integer=1`、`costCoins:integer=0或1`、`requiresRoll:boolean`。普通地图不添加这些成本字段。铁路要求STATION出发、STATION_ROUTE直接连接的另一STATION，一次1金币+1行动值（currentSpeedPoints）。普通移动不能利用铁路；所有免票停用，不耗历史次数。多站逐站提交。

```json
{"requestId":"每次新操作UUID","playerId":2,"stateVersion":118,"actionType":"USE_RAILWAY","payload":{"targetCellId":100086}}
```

这是请求结构示意，ID/版本从当前服务读取。普通及森林准备仅改actionType为MOVE_ONE_STEP。payload只接收targetCellId，不接收路径、骰点、属性、费用或最终位置。

### 8.2 森林准备与恢复

是否进入方向骰只看出发格MAZE；含B16/B19/B22。森林外进入直接结算；内部及离开森林都先准备。普通合法邻格才能准备，非法原目标无副作用拒绝。

准备响应 `data.resultType="CHECK_ROLL_PENDING"`、`data.movement=null`，扣一次1行动值，不改变位置。方向上下文最终统一使用 **pendingCheck.preparation**，**没有movementContext字段**。snapshot内的costSpeed=1、costCoins=0；socialCost=0只是原移动费用，不含后续自愿重投。

PendingCheck的新增业务值为FOREST_MOVE；businessSourceId=出发格。attributeType/attributeValue/modifier/difficulty/questId均为null，不渲染六维判定面板。preparation必有：fromCellId/requestedTargetCellId/fromQ/fromR/targetQ/targetR/directionIndex/costSpeed/costCoins/sourceId/cellId/socialCost（整数）、businessType/operationId（字符串）。directionIndex顺时针0～5，仅供呈现，不由前端提交。固定骰生效时fixedDice为整数，否则省略。

checkId、stateVersion、personalTurnNo、authorizationRound、expiresAt、canConfirm、canReroll、nextRerollSocialCost、禁止原因及rerollChain沿用原类型。GET checks/pending及player-view恢复同一准备；位置/个人回合改变的无效待骰仍按现有严格维护处理，不取消正常旧QUEST/WORK/招募快照。

隔离H2实际准备回执节选：
```json
{"checkId":17,"gameId":1,"playerId":2,"businessType":"FOREST_MOVE","businessSourceId":100038,"stateVersion":118,"authorizationRound":0,"status":"WAITING_ROLL","attributeType":null,"attributeValue":null,"modifier":null,"difficulty":null,"canConfirm":true,"canReroll":true,"nextRerollSocialCost":0,"preparation":{"fromCellId":100038,"requestedTargetCellId":100039,"fromQ":-1,"fromR":9,"targetQ":0,"targetR":9,"directionIndex":0,"costSpeed":1,"costCoins":0,"businessType":"FOREST_MOVE","sourceId":100038,"cellId":100038,"socialCost":0,"operationId":"8b3d797b-d3dc-4c97-be83-a9d1e19b4383"}}
```

准备费用把行动值扣到0仍可确认。等待期间持续心跳，不得另发移动、交易、用道具或结束回合。

### 8.3 授权与最终确认

`POST /games/{gameId}/checks/{checkId}/reroll` 请求 `{requestId:string,stateVersion:integer,authorizationRound:integer}`，不带dice。甜贝儿有效时每个人回合一条同check链，先免费再可付1社交；新重投新ID，网络重试原ID+原body。成功授权重新120秒，到期不再延长，但仍允许最终确认与系统代掷竞争锁。

`POST /games/{gameId}/checks/{checkId}/roll` 请求 `{requestId:string,stateVersion:integer,authorizationRound:integer,dice:integer}`。仅上传最新最终1～6点，不上传中间点数或历史最佳值。服务端固定骰优先；准备、重投、确认不重复扣移动费用或消耗固定效果。

最终2～5到所选格，1左偏60度，6右偏60度，以出发格为中心；固定6同样右偏。坐标顺时针 `(1,0),(0,1),(-1,1),(-1,0),(0,-1),(1,-1)`，与相机无关。偏移非法原地结算，不换另一侧、不重掷至合法、不退行动值。客户端自报点数不能证明随机公平，后端不验证中间物理投掷，本方案不提供防作弊保证。

森林roll的checkResult=null，submittedDice/effectiveDice为整数，追加movement。原属性业务含义不变，非移动roll省略movement。不发布伪属性CHECK_RESOLVED；只有实际移动才有ARRIVE_CELL，原地不清零014。

### 8.4 最终位移、费用与余额

普通/铁路结果在actions.data.movement，森林结果在roll.data.movement。保留全部from/requestedTarget/actualTarget的ID、格号和名字，及costSpeed、remainingSpeed。

| 字段 | 类型/省略 | 含义 |
| --- | --- | --- |
| costCoins | integer，新移动必有；历史可省略 | 本次票价，不是金币净差；铁路1，其余0 |
| coinsAfter | integer，新移动必有；历史可省略 | 完整事件与任务奖励后的实际余额 |
| movementOutcome | string，新移动必有；历史可省略 | MOVED或STAYED |
| stayReason | string，可省略 | STAYED的原因；MOVED省略 |

### 8.5 错误、重试与发布门槛

PARAM_INVALID用于未知目标模式、非法骰点或多余准备字段；EDGE_NOT_PASSABLE/RESOURCE_NOT_ENOUGH/ACTION_NOT_AVAILABLE/GAME_PHASE_BLOCKED/CHECK_ROLL_PENDING沿用现有拒绝语义。版本过期GAME_STATE_VERSION_EXPIRED、授权轮次CHECK_AUTHORIZATION_EXPIRED、无资格CHECK_REROLL_UNAVAILABLE、到期CHECK_DEADLINE_EXPIRED、已完成CHECK_ALREADY_COMPLETED、已取消CHECK_CANCELLED、同ID异内容REQUEST_ID_CONFLICT。

超时不等于操作失败，先刷新服务端状态；需要网络重试时原路径、requestId和全部原body不变，不能悄悄换版本。刷新后不同操作才用新ID。已保存首次响应不会被当前玩家状态改写，也不能拿旧回执覆盖客户端更高版本视图。

本批无新增DDL/配置写入，提供只读预检。部署前仍核对累计结构；回退旧程序前必须处理FOREST_MOVE待骰，不能交旧损坏扫描误取消。不清库、不改地图，不用重建已有测试局切换规则。当前仅本地验收；正式部署和Godot实现均不在本批操作内。
