# 道具系统与任务详情：客户端本次接入交接

日期：2026-11-05。目录入口：[README](README.md)。通用契约：[ES完整API文档](ES完整API文档.md)。本文件说明现有后端能力，不开发新玩法、不修改Godot源码。

## 1. 本次交接范围与上线状态

本次客户端接入：背包/道具详情、基础装备与消耗品操作、有效属性与持续效果展示，以及个人任务详情/进度表、待提交状态、主动提交和结算页面。商店和奖励领取复用现有入口，不新建第二套库存或奖励机制。

已部署记录为2026-11-04任务提交版本，公网`http://182.92.234.193:8080`，API前缀`/api/v1`；依据后端运维部署报告，`questSubmissionVersion=1`、`movementRulesVersion=2`已在公网新鲜player-view确认。本轮未重新执行公网道具/领奖动作，不能把部署、隔离测试或文档当作Godot已验收。

本局/玩家使用实时身份，不硬编码示例gameId/playerId。新鲜player-view必须确认任务提交能力；movementRulesVersion不是任务能力版本。074、调查、宝藏、Boss、偷窃及旧版复杂特殊道具不在本次接入范围；也不因本次优先级调整而关闭其他既有接口。

## 2. 必须复用的接口

以下为完整路径；局内接口均需`Authorization: Bearer <accessToken>`。带JSON的POST使用`Content-Type: application/json`。

| 方法与路径 | 请求 | data与用途 |
|---|---|---|
| GET /api/v1/games/{gameId}/player-view | 无body | 对局版本、身份、当前位置、有效六维、剩余资源、持续效果、阶段、队首与待骰 |
| GET /api/v1/games/{gameId}/available-actions?playerId={自己} | 无body | 行动级available/reason/reasonText，不是每张道具的完整资格 |
| GET /api/v1/games/{gameId}/shop/current?playerId={自己} | 无body | 本局公共货架、真实shelfSlotId、价格、位置资格及库存版本 |
| GET /api/v1/games/{gameId}/items?playerId={自己} | 无body | 自己HAND/EQUIPPED物品及totalCount |
| GET /api/v1/games/{gameId}/quests?playerId={自己} | 无body | quests与completedQuests，任务详情、objectives/conditions/submission |
| GET /api/v1/games/{gameId}/quest-offers?playerId={自己} | 无body | 公共任务候选，不是自己的任务进度 |
| POST /api/v1/games/{gameId}/actions | 下节统一请求 | 购买、道具操作、任务目标行动、主动提交、奖励领取/放弃 |
| GET /api/v1/games/{gameId}/checks/pending | 无body，不传playerId | 自己已有待骰；复用已接入骰子UI |
| POST /api/v1/games/{gameId}/checks/{checkId}/reroll、/roll | 沿用现有骰子契约 | 任务判定目标的重投授权与最终确认，不另造任务骰子接口 |

没有独立的GET /items/{playerItemId}或GET /quests/{playerQuestId}详情路由。详情页从既有列表按实例ID选择，必要时重查列表；不要自行拼新URL。

`GET /api/v1/characters`已有初始角色资料，可复用已有角色缓存展示基础属性。不要混用userId、房间成员ID和局内playerId。

## 3. 统一行动和实例编号

下例仅为请求结构说明，不是可直接使用的公网身份：

```json
{
  "requestId": "677c02f0-1ca1-4caa-b966-385ad8e4be22",
  "playerId": 1001,
  "stateVersion": 12,
  "actionType": "EQUIP_ITEM",
  "payload": {"playerItemId": 801}
}
```

- itemId：道具种类，用于卡图/名称映射，不用于操作具体持有物。
- playerItemId：自己这次持有的道具实例，装备/使用/卸下/出售/丢弃/任务提交使用它。
- shelfSlotId：货架当前商品位置实例，购买时使用；不能用itemId或数组序号替代。
- playerQuestId：本次任务接取实例，同名重接不合并。
- rewardId/cardId：队首奖励及该批候选实卡编号，不能用itemId替代cardId。

每次新逻辑操作生成新UUID并禁用重复点击；网络结果未知时重试原requestId、原URL、原完整body（包括stateVersion）。不要改旧ID内容；新操作才用最新版本。重放可能包含旧视图，不覆盖更高版本状态。

| itemId | 名称 | 类型 | 当前效果 |
|---|---|---|---|
| 1003 | 苹果 | CONSUMABLE，消耗品 | 使用后有效速度属性+2，持续使用当个人回合 |
| 1005 | 花束 | CONSUMABLE | 使用后有效心灵、魅力各+2，持续使用当个人回合 |

## 5. 背包与道具详情字段

items查询data对象为：`gameId:integer`、`playerId:integer`、`totalCount:integer`、`items:array`、`pendingChoices:array`。当前新引擎pendingChoices为空兼容数组，实际待领取队首读player-view.engineState.pendingReward，不能因pendingChoices为空漏掉奖励。

items每项的实际字段：

| 字段 | JSON类型及用途 |
|---|---|
| playerItemId、itemId | integer，分别为持有实例和种类 |
| itemName、itemType、itemTypeText | string，名称及类型/中文 |
| itemCategory | string/null，食品/杂物/法器等实际分类 |
| buyPrice、sellPrice | integer/null按实际返回显示；不能从旧表写死 |
| description、itemTag | string/null，展示文字/标签，不解析成可执行规则 |
| location、locationText | string，HAND手牌或EQUIPPED装备 |
| createdAt | string/null，当前新引擎可为null，不强制解析 |

没有每卡canUse/canEquip或结构化attr_delta字段，不能从API未提供的字段假造按钮资格/装备加成。卡面属性文字可展示，真实总属性从player-view读取。装备区由location筛选，后端未提供固定装备槽编号；最多2件，不擅自设计部位限制。

手牌和装备均计入totalCount；当前容量按初始角色力量，不按有效力量扩容，接口没有capacity字段。若界面展示容量，可复用初始角色配置，不拿药剂/蹄铁后的effectiveAttributes.strength当背包上限。

## 6. 道具操作准确payload与返回

所有下列action均走/actions：

| actionType | payload | 当前规则/关键结果 |
|---|---|---|
| SHOP_BUY_ITEM | `{"shelfSlotId":31}` | 在SHOP，1社交+实际价格，容量足够；shopBuy.boughtItem含新playerItemId，newShelfItem可null |
| SHOP_SELL_ITEM | `{"playerItemId":801}` | 在SHOP，1社交，按实际sellPrice入账；HAND/EQUIPPED均可卖，结果读取itemSell，不是shopSell |
| SHOP_REFRESH | `{}` | 在SHOP，2社交，刷新本局公共货架；shopRefresh.items是刷新后列表 |
| EQUIP_ITEM | `{"playerItemId":801}` | HAND且EQUIPMENT；已有2件时另传replacePlayerItemId指定自己当前装备 |
| USE_ITEM | `{"playerItemId":801}` | HAND且CONSUMABLE；生效后卡弃置，持续效果独立保存 |
| PLAY_ITEM | `{"playerItemId":801}` | 可兼容按类型分派装备/使用，但UI不能让一次点击同时调用PLAY_ITEM和EQUIP_ITEM/USE_ITEM |
| UNEQUIP_ITEM | `{"playerItemId":801}` | EQUIPPED回HAND，手动卸下每个人回合1次；满槽替换共用卸下次数 |
| DISCARD_ITEM | `{"playerItemId":801}` | HAND或EQUIPPED进入弃牌，手动丢弃每个人回合1次 |

装备、使用、卸下和手动丢弃当前不额外收金币/社交，但仍受自己的可行动回合、原次数、待办/待骰与实际校验；不要把“没有费用”等同于随时可操作。

EQUIP/USE/PLAY/UNEQUIP/DISCARD的响应业务对象为`data.itemUse`，字段包括playerItemId、itemId、itemName、itemType/itemTypeText、locationAfter/locationAfterText、replacedPlayerItemId、speedDelta/speedAfter、socialDelta/socialAfter、fromCellId/toCellId。当前属性装备/消耗品的speedDelta/socialDelta为0，它们不是六维增量；真实六维从playerViewState.players[].effectiveAttributes读取。

出售读取`data.itemSell`的sellPrice、coinsAfter、prestigeAfter、locationAfter等；当前新引擎出售后的卡去DISCARD，不依赖旧SOLD字面值。购买读取`data.shopBuy`；刷新读取`data.shopRefresh`。

成功后先应用playerViewState与newStateVersion/nextAvailableActions，再重查items及需要的shop/current；GET inventory本身没有stateVersion，需用请求序号/界面代次防止先发旧查询后到覆盖。无需固定延时等后台补货：正常行动响应成功时其事务已提交。

## 7. 有效属性与持续效果

自身player-view.players项包含：

- effectiveAttributes：strength/speed/social/charm/magic/mind，当前有效六维；不是剩余可消耗资源。
- currentSpeedPoints/currentSocialPoints：当前剩余行动值/社交；不由前端随装备改动补满。
- activeItemEffects：当前有效的消耗品属性效果数组，不包括所有装备；装备没有此条目不代表未生效。

每条持续效果字段为effectId、itemId/playerItemId/gameItemCardId（来源可空）、operationId（可空）、durationBasis、startsPersonalTurn、expiresPersonalTurn、currentPersonalTurn、status、effective、attributes。attributes为六维增量整数映射。durationBasis为PERSONAL_TURN；起止包含首尾，以服务端状态为准，不能客户端倒计时删效果。药剂多层按effectId分别展示，不合并后刷新旧层到期时间。

## 8. 任务详情与进度表

从GET quests的data.quests找本人当前任务，data.completedQuests找已完成实例；详情页按playerQuestId选择，不新建详情路由。公共quest-offers只是候选，不含本人已做进度。

- 详情：questName、background、description、rewardText、locationText、status/statusText及实际费用/属性说明字段，值可空时不强行补造。
- objectives：objectiveKey/text/completed/currentValue/requiredValue/unit/successful/stateAvailable。按completed划线/打勾；按数值与单位展示2/5金币等，不把progress平均分配给每个目标。
- conditions：conditionKey/text/satisfied，是当前可变条件，单独展示。离开地点可变false，不撤销已经完成目标，达标锁定后不据此禁止提交。
- objectivesStatus和objectiveNotes：若不可用/部分证据不足，显示说明，不猜测完成。可选checkAttributes/stayState只在返回时展示；不能用014的计数资格替代提交资格。
- questUpdates是增量，缺少某任务不代表它被删除；动作后用更新快照，切回合、重连及打开详情时用GET quests刷新当前资格。

普通任务状态已部署为`IN_PROGRESS → READY_TO_SUBMIT → COMPLETED`。READY仍占任务栏、目标和奖励锁定；未正式提交不入账、不抽奖励、任务实卡不弃置。END达标最早下一个自己的MIDDLE提交；可以按原ABANDON_QUEST规则扣1声望放弃。

submission字段：protocolVersion、targetsLocked、achievedPersonalTurn、earliestSubmitPersonalTurn、canSubmit、unavailableReason、rewardPreview、rewardPaid。未达标时预览及回合字段可null；旧完成历史不伪造达成证据，旧响应也可缺submission。完整原因码及类型见[任务专项](普通任务主动提交与结算页面交接.md)。

rewardPreview.coins为冻结基础/边际金币，partnerCoins单列，预览总额为两者之和。rewardPaid.coins已包含伙伴加成。列表原rewardCoins等仍可能是配置，不能当作已到账。

## 9. 任务目标行动、提交与结算页面

不要混淆两种“提交”：SUBMIT_QUEST_ITEM是消耗真实道具推进任务目标；SUBMIT_QUEST是目标达标后的正式结算。

| actionType | payload | 说明 |
|---|---|---|
| ACCEPT_QUEST | `{"questId":149}` | 公共候选中实际questId，不用offerId/slotNo |
| SUBMIT_QUEST_ITEM | `{"questId":142,"playerQuestId":401,"playerItemId":801}` | 真实道具消耗进弃牌，不发动药剂等使用效果 |
| PAY_QUEST_RESOURCE | `{"questId":107,"playerQuestId":401}` | 后端按任务配置扣费，不提交自定金额 |
| QUEST_SOCIAL_CHECK / QUEST_FULL_SOCIAL_CHECK | `{"questId":149,"playerQuestId":401,"attributeType":"SPEED"}` | 按真实任务/返回资格准备，再复用现有骰子流程 |
| SUBMIT_QUEST | `{"playerQuestId":401}` | 只接受实例ID，不传questId/金额/dice/完成标志 |
| ABANDON_QUEST | `{"questId":149,"playerQuestId":401}` | 按原1声望规则，支持待提交实例 |

SUBMIT_QUEST只在RUNNING、本人MIDDLE、达到最早个人回合且无暂停/待骰/奖励队首时允许，不额外收费、不重查旧地点/持物。按钮优先取submission.canSubmit和稳定原因，最终以提交响应为准。

成功data.questSettlement含playerQuestId、questId、coinsGranted、prestigeGranted、partnerBonusCoins、coinsAfter、prestigeAfter、pendingItemRewardCount，均为当前实际结算数字。coinsGranted已含partnerBonusCoins，加成只作明细不能再相加；pendingItemRewardCount为实际待选奖励数，不是已入背包物品数。

前端提交成功先显示本次结算页；该页“确认”只打开已创建的playerViewState.engineState.pendingReward，不第二次调用SUBMIT_QUEST或另造领奖接口。无实际候选时不弹空选择窗口；deckDraws提示牌库不足时按实抽数量展示。

## 10. 道具奖励领取与行动阻塞

完整队首及ITEM候选结构、字段可空规则和真实隔离HTTP JSON见[ITEM奖励候选准确契约](ITEM奖励候选准确契约.md)。候选顶层cardId用于领取、itemId用于卡图；名称在configuration.item_name，不在顶层itemName。候选还有canExecute、executeUnavailableReason、capacitySatisfied和本局configuration。领取必须同时满足队首与该候选canExecute；不要仅凭canResolve启用。

复用/actions，actionType为RESOLVE_TURN_START_EFFECT：领取payload为`{"rewardId":71,"cardId":901}`，放弃为`{"rewardId":71,"abandon":true}`。这是通用FIFO名字，不只在回合开始使用。两者都用新的requestId和最新版本。

只处理服务端队首及本人候选；查看canExecute/canAbandon和原因。背包满不能强制领取，也不能自动替玩家丢弃。奖励队首期间只做服务端允许的合法整理，当前包括装备、卸下、丢弃、放弃任务；不能借整理名义使用消耗品或交易。次数、声望和本人回合限制仍有效，且装备不减少总负重，未必能解除满包。

确认领取成功后再刷新背包；未选/放弃奖励回牌堆并洗牌，使用/出售/丢弃/任务提交进入弃牌堆，按既有耗尽回收。不能在客户端自行退卡、补货、补抽或退款。

## 11. 策划、客户端与验证要求

- UI范围：复用现有背包/卡牌显示、装备区、道具详情、任务详情和进度表；复用投骰及奖励FIFO，不重建地图、不改现有相机或棋子系统。
- 卡图复用现有CardArtCatalog和已核对资源，按实际itemId/questCode映射。缺图/文字/必要字段先列出，不擅自增加后端字段、下载新素材或解析中文猜逻辑。
- 持续心跳和轮询；弹窗遵守blocks_map_input，点击卡/按钮不能穿透成地图移动。关闭详情页不销毁对局或中断连接。
- available-actions是行动级提示，不等于每张卡都可用；资源、实例、次数等并发拒绝显示实际错误后刷新，不匹配中文文本做状态机。
- REQUEST_IN_PROGRESS原请求重试；REQUEST_ID_CONFLICT核对原请求；版本过期刷新后仅新逻辑操作用新ID。其他PARAM_INVALID/AUTH_PERMISSION_DENIED/ACTION_NOT_AVAILABLE/GAME_PHASE_BLOCKED/CHECK_ROLL_PENDING/GAME_REWARD_CAPACITY/GAME_RESOURCE_NOT_ADMITTED按主契约处理。
- 先完成本地模拟、DTO、构建/相关测试及实际Godot UI检查；原有静态检查失败要区分基线。模拟/无界面通过不等于公网联调，公开报告不得记录密码、令牌。
- 公网写入测试须用户指定并批准测试账号/对局；没有授权不得注册、建局、发心跳、移动、使用道具、提交任务或领奖。本轮文档整理没有执行这些操作。

最低测试：购买后实例入包；装备/卸下与2件替换；消耗品使用/叠加/到期及不补行动值；每回合整理次数；满包队首处理；不同任务目标/条件/部分进度；达标待提交锁定；014 END达标下回合提交；结算实际收益；选择奖励确认不重复发奖；幂等重试及重连；已实现移动/铁路/森林/打工不回归。

需要用户决策的点：本轮未发现新增玩法项。具体UI布局、缺素材或接口未提供的必要能力，由策划列出后请用户决定，不擅自改服务端规则。
