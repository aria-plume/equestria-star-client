# Godot 道具购买、背包使用与装备接入记录

更新时间：2026-11-07。

本记录描述客户端本批接入范围；准确接口字段和服务端规则仍以 `ES完整API文档.md` 与 `道具系统与任务详情接入交接.md` 为准。

## 已接入范围

- 公共货架的“购买”提交 `SHOP_BUY_ITEM`，payload 只包含 `shelfSlotId`。
- 左下角“道具”每次打开重新请求 `GET /games/{gameId}/items?playerId=...`，只展示 `location=HAND`，按 `playerItemId` 保留重复实例。
- 左下角新增“装备”入口，每次打开同一接口，只展示 `location=EQUIPPED`。
- 消耗品使用提交 `USE_ITEM {playerItemId}`，必须经过包含道具名称的二次确认。
- 装备提交 `EQUIP_ITEM {playerItemId}`；装备栏已有两件时由玩家明确选择 `replacePlayerItemId`，取消不发送请求。
- 卸下提交 `UNEQUIP_ITEM {playerItemId}`，成功后以重新查询的持有位置为准。
- 卡图继续按 `itemId` 映射；所有实例操作使用 `playerItemId`；购买使用 `shelfSlotId`。
- 不发送旧的 `PLAY_ITEM`，也不根据卡面或中文原因在本地推演道具效果。

## 权威状态与失败边界

- 所有写操作使用当前 `gameId`、局内 `playerId`、最新 `stateVersion` 和每次逻辑行动唯一的 `requestId`。
- 按钮只使用 `available-actions` 的行动级资格；每张卡的最终资源、容量、次数和效果仍由服务端提交校验。
- 写操作与移动、结束回合、任务、打工互斥；快速重复点击只允许一个请求进入提交链路。
- 成功后先应用 `playerViewState`/新版本，再刷新资格和 `/items`；购买额外刷新 `/shop/current`。
- 成功但后续 GET 失败会显示“操作已成功、刷新失败”，不会重新提交写行动。
- 网络超时或未知结果不会生成新 requestId 自动重发；保留原请求身份，随后只同步权威视图和列表。
- HUD 六维、金币及其他玩家状态继续来自权威 `player-view`，客户端不自行应用苹果或装备效果。

## UI 与输入

- 背包和装备区复用中央暗色卡牌层，卡面保持纵向比例并支持横向滚动，不限制三张。
- 使用确认、满槽替换选择、取消、卡牌按钮和滚动区域均位于 `blocks_map_input` 输入层，不穿透到地图。
- 灰色按钮不会提交，也不会关闭弹层；弹层外既定关闭区域仍按原规则关闭。
